# 插件更新审阅与旧包恢复界面

第十三阶段，2026-09-13。本阶段将通用安装前审阅加入平台插件管理页，不增加平台实现或业务开关。
这是一次管理基础能力的本体/Host/Web 更新。Host SDK 2.10、Abstractions、平台 API 和 schema 保持不变，
现有插件不必重编；但旧安装的播放器不会凭更新插件获得这个新的管理界面。

## 使用流程

1. 在设置 → 平台插件批量选择或拖入新包。预览显示候选版本、SHA-256、当前选择版本和当前 SDK。
2. 阅读提供方、能力、页面、设置键/类型、宿主特性以及凭据别名、旧设置别名、图片域名的增删。
3. 访问声明变化时默认展开差异；即使没有变化，也要重新确认来源和信任。
4. 确认导入后默认关闭。明确启用，再正常重启应用；导入本身不切换当前播放。
5. 要恢复较低版本，在对应行点“选择旧版包”，由原生文件选择器选择自己保存的完整包，继续相同确认流程。

恢复入口要求当前选择通过完整性检查，选中包具有同一插件 ID、版本更低且兼容。没有扫描私人文件夹、
下载历史包或静默选取旧修订。不能保证所选文件就是历史安装过的原包；请自行核对来源及压缩包摘要。
旧修订和收藏引用仍保留，缺失能力或提供方的引用不会自动迁移/删除；恢复不撤销账号或设置变更。
若原选择损坏，可以用普通导入修复，不能把不可信的原选择当作验证通过的恢复基线。

## 安全与兼容边界

界面用正式管理器读取实际候选及当前选择；确认前重新核对原选择、启用偏好、内容和完整性。
审阅后有变化则拒绝这次提交，重新选择后再次批准；不使用用户可改的 UI 字段决定批准范围。
新包也会重新校验暂存内容。失败/取消保持原选择；批次错误逐项报告，成功项照常默认关闭。
离开管理页会撤销尚未提交的审阅；选择器之后才返回的结果也会取消，不在后台保留信任勾选。
已提交的确认不会因页面离开被宣称为回滚。同一预览的普通状态刷新保留焦点、展开状态和勾选，
新预览则重置批准。管理卡片不使用延迟布局跳过，避免高缩放窄窗口中审阅区域出现空白。

这不是将第十二阶段 `update-plan.json` 当成可执行安装说明。开发工具的交付/兼容矩阵仍是独立验收入口，
应用内只报告静态清单兼容，不自动执行插件 DLL、登录、网络、播放或开发测试。
声明差异不是完整代码审计：同名页面/设置的业务语义、代码权限、默认值等不在标识增删摘要之内。
旧版展示的是展开内容摘要，与候选的 ZIP SHA-256 不同；哈希不是发布者签名。同进程插件不是沙箱。

## 验收方式与限制

`PluginUpdateReviewTests` 使用正式管理器和原始不可执行夹具，覆盖首装、更新、重新导入、权限声明、
取消、选错身份/版本、原选择或暂存内容变化、默认关闭和原包保留。没有用户数据或账号。
`tools/Test-PluginSettings.cjs` 使用隔离 Edge 和合成 Native 回调，覆盖中英文、深浅色、1/1.5/2 缩放、
窄/矮窗口、键盘、减少动画、确认/刷新/取消/迟到回调及转义；也对发布输出运行。
浏览器缩放和合成窗口状态不是 Windows 跨屏 DPI、原生选择器或安装版重启验收。
没有签名安装包、用户安装更新、仓库推送或 Release；既有真实平台问题不因本阶段离线通过而解决。
