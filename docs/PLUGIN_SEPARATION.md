# 可选在线插件：使用与开发

这是公开播放器的当前插件指南，不依赖私人平台仓库、账号、媒体或构建输出。
Host SDK 2.0.0，运行清单 schema 5，平台 API 1，Abstractions 1.2.0；播放器版本与 SDK 版本独立。

## 插件与播放器的边界

具体在线平台的 API、认证与续期、媒体地址解析和平台专属规则属于独立插件，不随默认播放器分发。
公开核心负责归一化数据、能力路由、信任与生命周期，以及原有页面、音频调度和视频合成。
用户没有导入、批准并启用对应能力时，不显示虚构的平台账号、音质或网关设置。
本地库、搜索、队列、LRC、音效、Windows 集成和局域网功能可以保持内置，不需要在线插件。

平台 ID 和实体 ID 是插件拥有的稳定不透明标识。核心不把它们当作本地路径，也不按标题猜测歌曲身份。
混合歌单保存引用和非敏感元数据，不保存 Cookie、Token、签名 URL 或请求头，不写入本地 library.json。
插件缺失/停用时保留收藏，恢复同一身份的插件后再解析元数据与短期播放租约。

播放器在登记搜索、歌单和分段的播放句柄前，检查返回曲目/歌单的来源归属以及附带视频的来源归属。
空行、默认实体ID或跨来源结果返回InvalidResponse，整页拒绝，不静默改写为当前来源或用旧缓存冒充成功。
收藏补元数据（TrackDetails或精确ID搜索回退）也检查视频归属；拒绝时保留原收藏身份和可用回退信息，不修改收藏文件。
这是播放器消费结果的边界检查，不是任意插件代码的安全沙箱，也不代表全部业务返回字段都已经验证。

## 导入、启用和更新

1. 在 **设置 → 平台插件 → 批量导入插件** 多选 `.auralis-plugin` 或 `.zip`，也可拖入播放器内容区域。
2. 核对来源、名称、版本、能力、SHA-256 和精确凭据访问声明；只有主动勾选信任后才能确认。
3. 新包和更新包默认关闭。单独启用后点击重启，或从托盘完全退出再重新打开。

每批最多 16 个包，压缩总量和展开暂存总量各不超过 256 MiB；单包压缩/展开各不超过 128 MiB。
平台包为含 platform.plugin.json 的平面 DLL/JSON 压缩包，2–64 个文件；不是源码 ZIP 或任意安装程序。
同批重复插件 ID 的所有项均拒绝；其他无效包逐项报错，不阻止用户确认有效项。取消不改变源文件。
导入只检查文件与元数据，不执行 DLL；首次明确能力调用才惰性激活已批准、启用的包。

更新写入新的不可变修订，不覆盖正在运行的 DLL。启用/更新在下次启动生效；停用立即阻止后续调用。
更新后但尚未重启时，停用仍清理当前会话的旧修订账号与登录资料，不使用待生效新版的清单。
损坏包不执行清理代码；已发出的凭据访问会被撤销，无法确认完成的清理会报告失败，而非显示已清空。
原生登录会话是可选能力。只有声明NativeLogin的provider才执行网页登录资料清理；只有Authentication的provider仍可正常断开账号。
宿主将后台Closed事件调度到UI线程，隔离Show/Activate/Close及取消回调异常，避免一个可选登录插件阻止退出或重试。
停用按批准声明撤销凭据并通过插件清理隔离登录资料，失败会报告清理未完成，不虚报账号已删除。
目前没有图形卸载/回滚入口。不要手改安装目录、清单、摘要或批准记录。

## 旧包升级

当前播放器要求 schema 5。schema 1–4 可被离线识别，但管理页显示“需要升级插件”，不能启用或导入。
旧收藏、设置、账号和原包保留。获取同 ID 的完整新版包，经正常导入授权、启用和重启后使用。
核心不再内置平台凭据地址或图片域名回退表；无法确认旧包清理地址时报告清理未完成。
仅改 JSON 版本不能替代完整升级，也不能证明旧 DLL 的设置、账号和播放行为正确。

## 插件声明

- 设置由清单声明为 `choice` 或 `endpoint`，只保存非敏感偏好；没有固定平台音质/网关字段。
- `credentialAliases` 声明精确旧账号地址并在导入时批准；没有声明的键留在插件自己的作用域，不扫描或复制账号库。
- `commentArtworkDomains` 每个来源必须显式给出；空数组拒绝全部。仅允许声明域和子域的标准 HTTPS 评论图片。
- 账号、搜索、歌单、歌词、视频、评论等 UI 入口依赖声明能力及当前曲目数据；插件不能任意注入主页面脚本。

详见 [兼容性与清单](PLUGIN_COMPATIBILITY.md)、[设置协议](PLUGIN_SETTINGS.md)及[凭据声明](PLUGIN_CREDENTIALS.md)。
这些文档的历史特性引入版本不应当替代当前运行门槛。

## 构建与验证

公开源码可以在没有具体平台源码或已安装插件的情况下构建：

```powershell
dotnet restore Auralis.sln
dotnet build Auralis.sln -c Release --no-restore
dotnet run --project Auralis.Tests -c Release
dotnet run --project Auralis.Platform.Host.Tests -c Release
dotnet run --project plugin-sdk/ContractCheck.Tests -c Release
```

开发者自行实现公开 Abstractions 契约，用 `plugin-sdk/ContractCheck` 检查自己的解包目录。
`--inspect` 不执行代码；合法旧清单也可能 Passed=true，必须同时检查 RuntimeManifestCompatible。
`--verify --trust-plugin-code` 由独立超时 worker 检查可信 DLL 的接口/生命周期，不调用登录、搜索或播放。
正确命令格式、退出码和作者行为夹具见[契约自检说明](../plugin-sdk/ContractCheck/README.md)。

自检通过不代表真实账号有效、平台在线或媒体可播放；升级仍需验收登录、续期、音视频切换、收藏和评论。
同进程插件不是恶意代码沙箱，SHA-256 不认证发布者。不要安装不可信代码，不绕过 DRM、付费、地区或平台验证。
