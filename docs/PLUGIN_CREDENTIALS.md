# 插件旧账号兼容声明

当前规则（2026-09-08，Host 2.0）：隐式平台凭据表已删除，任何清单格式都不推测平台账号地址。
生产播放器只启用 schema5；旧包显示需升级，不修改原包/批准/账号/设置。已批准新包通过精确 credentialAliases 继续访问原地址，
刷新和撤销也使用同一声明地址。关闭不能安全清理的旧包会报告清理未完成，不虚报已清空。
声明机制在 schema 3 引入；当前完整包须使用 schema 5 和 credential-aliases.v1，见 PLUGIN_COMPATIBILITY.md。
这里保留的是精确地址兼容，不是复制用户 Cookie；插件 API 和 Abstractions 程序集身份不变。

更新后尚未重启时，停用以当前会话的不可变修订为准：关闭旧 provider 的登录会话，撤销旧修订已批准的凭据地址，
并调用旧修订的独立登录资料清理。不得用待重启新版的账号声明替代当前会话的声明。
若当前修订损坏，仍撤销已经发出的凭据作用域并清理其已批准地址，但不执行损坏包、不猜测尚未批准的地址；返回清理未完成。
撤销同时阻止迟到激活创建新的可写作用域。新修订与真实账号的迁移仍需显式启用和重启，不自动改写用户数据。

## 声明与批准

清单顶层可声明精确地址，例如一个虚构插件：

```json
{
  "schemaVersion": 5,
  "credentialAliases": [
    { "key": "session", "scope": "example.previous-plugin", "legacyKey": "account.v1" }
  ]
}
```

这个片段需与完整清单的 ID、版本、hostRequirements、入口及 providers 一起使用。最多 16 项；key/legacyKey 最长 96，
scope 最长 64，只允许 ASCII 字母、数字、点、横线、下划线，并以字母或数字开头。
不接受通配符、路径、URL、空值、重复 key、重复目标或未知字段。key 按大小写精确匹配。
scope 指 WindowsPlatformCredentialStore 的逻辑作用域，不是文件路径；实际 Windows 地址仍由宿主构造。
清单只保存地址，不保存秘密值。没有声明的 key，包括临时登录挑战，留在插件自己的作用域。

导入预览单独展开「旧账号兼容访问」，列出插件名及 key → scope / legacyKey。
用户勾选信任时同时批准这些地址的访问；不接受时取消导入，不注册包。
新导入和更新包仍默认关闭，启用后重启生效，不自动迁移或登录账号。

安装批准记录升级为 schema 2：除完整文件 SHA-256 外，记录 CredentialAliases。
记录必须与清单声明精确一致。仅有旧 hash-only 收据、遗漏/多出/变更地址，均拒绝发现和激活。
新格式无别名的包可以使用空批准集合；不能因为其 ID 恰好等于历史平台 ID 而获得旧地址。
构建工具仅为显式生成的隔离构建目录产生开发批准记录，不批准用户已安装目录。

## 生命周期

- 清单发现只验证 JSON、路径和文件摘要，不加载 DLL、访问凭据或创建网络客户端。
- 第一次明确能力调用后，Host 将已通过完整性校验的清单交给 IManifestPlatformHostContextFactory。
- DefaultPlatformHostContextFactory 固定当前会话的地址规则，DeclaredPlatformCredentialStore 按精确键路由。
  登录读取、会话刷新写入和退出删除均操作同一地址；没有遍历或复制整个凭据库的操作。
- 停用先撤销读写并等待已开始的写入结束，再删除固定清单中列出的地址；即使插件没有
  Authentication 能力也执行这一步，覆盖服务凭据。之后仍由插件 SignOut/ClearLoginData 清理其其他会话和隔离浏览器 Cookie。
- 删除失败明确返回清理未完成，允许重试；不因部分失败重新启用插件。迟到刷新不能恢复已撤销账号。
- 损坏或未批准清单不能决定清理地址，也不能执行清理代码。恢复可信包后再重试。

## 旧包升级与限制

当前播放器拒绝运行/导入 schema 1–4，管理页保留已安装旧包并说明需要升级。
所有格式与 ID-only 上下文都不再使用平台名回退。仅有相同 ID 不能获得别的作用域账号。
通过应用内导入同 ID 的完整新版包，确认授权、启用并重启；不要手改旧清单或批准记录。
账号持有人仍需验收实际登录保持、会话续期和退出；合成凭据测试不能证明真实平台会接受原会话。

本轮没有将历史凭据复制到新 scope，也没有取消平台原本的权限、有效期或登录校验。
上述约束是宿主服务接口与意外混用防护；受信任 DLL 在播放器进程内执行，**不是恶意插件沙箱**，
SHA-256 不是发布者认证，同一 Windows 用户下的进程仍可能修改本地批准文件。

## 验证

`CredentialAliasTests`：严格清单校验、旧收据拒绝、精确授权、真实 DLL 惰性激活时传递清单、
导入确认/默认关闭、生产 context factory 注入合成字节存储后的读取/刷新/清理/隔离、旧格式兼容。
`PluginManagerTests` 在 AURALIS_PLUGIN_PACKAGES 指向自备新包时覆盖独立导入，以及真实清单声明驱动的
合成账号保持、刷新和停用删除；不访问 Windows 凭据库。
`Test-PluginSettings.cjs` 覆盖权限提示、转义、长地址换行、无声明时隐藏、中英文、键盘、
light/dark × 1/1.5/2 渲染比例（1.5 使用 reduced motion）。这些不是原生跨屏 DPI 或真实平台登录测试。
