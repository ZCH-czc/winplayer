## Failures and limits retained

- The service test failed twice using the default temporary directory: enumeration reported one uppercase
  `STREAM-….MP3.tmp` entry, but immediate exclusive opening returned FileNotFound (0x80070002).
  A separate default-directory transport test also failed its post-shutdown empty-directory assertion.
  The service assertion was not removed or relaxed. Three fixed service runs in a dedicated temporary directory
  passed; the default-directory intermittency is **not fixed or conclusively attributed to an external process**.
- No installed-app native picker/restart, real cross-monitor DPI, real-account, or audible device acceptance was performed.
- An external module's anonymous live search returned a typed service-unavailable result. Offline/contract checks do not override that failure.
- Full delivery reports retain `ReleaseReady=false` where native/live acceptance is missing. A controlled-test
  prerelease must not be presented as the full production delivery gate passing.
- Public binary distribution requires the repository's signing policy or an explicit owner-approved test-release
  exception. A self-signed certificate is not a Windows-trusted production identity.

Raw local reports and synthetic test state remain in ignored artifacts; no personal paths, receipts, accounts or signing secrets are release attachments.

## Next stage

Keep this SDK frozen. First resolve the default-temp cleanup intermittency and complete installed-app/native plus
real-service acceptance, without borrowing credentials or bypassing service restrictions. Then exercise a new
module-only revision through the same exact-package gate and a private CI workflow. Only add host capabilities
when a concrete feature cannot be expressed by the existing contract; separately pursue a production signing chain.
